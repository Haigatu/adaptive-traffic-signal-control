# ATSC: рабочая симуляция и обученные модели

Это воспроизводимый **пилотный эксперимент**, реализованный по материалам постера. Он включает настоящую микроскопическую симуляцию Eclipse SUMO, обучение четырёх прогнозаторов на PeMS04/08 и три варианта D3QN. Результаты вычислены из запусков; улучшение заранее не гарантируется.

В выполненном пилоте D3QN не превзошёл лучшие базовые контроллеры по задержке. Safety-кандидат отклонён: снижение TTC-событий сопровождалось чрезмерным ростом задержки. Это результаты ограниченного обучения, а не доказательство неработоспособности подхода.

**Продолжение:** добавлен отдельный вариант D3QN с четырьмя таймерами и ограничением времени без зелёного до 120 секунд, включая жёлтый. Выполнены 30 дополнительных эпизодов, выбор checkpoint по validation и 60 новых тестовых прогонов. Итоговые числа и сравнение эффекта ограничения с эффектом обучения — в [английском notebook](notebook/Results_Evidence.ipynb), раздел 6. Первоначальные веса и результаты сохранены отдельно.

## Что открыть

Старые HTML-отчёты и записи удалены из текущей версии. Notebook анализирует сохранённые результаты; интерактивная демонстрация запускает SUMO через `demo.cmd`.

## Новый агент с ограничением ожидания

После установки зависимостей и загрузки данных:

```bash
python -m atsc.continuation evaluate --workers 3
```

Эти команды используют сохранённый `artifacts/continuation/selected.pt`, выбранный по минимальной средней validation-задержке среди дополнительных эпизодов 0/10/20/30. `candidate_030.pt` — результат всех 30 дополнительных эпизодов, независимо от выбора validation. Для возобновления прерванного 30-эпизодного запуска: `python -m atsc.continuation train --resume`. В поставляемом завершённом запуске эта команда не добавляет эпизодов. Для независимого повторения сначала сохраните копию и перенесите каталог `artifacts/continuation`, затем запустите `python -m atsc.continuation train`.

`resume.pt` содержит online/target сети, optimizer, replay buffer, состояния RNG и историю. Сохраняется на границе эпизодов; при прерывании текущий незавершённый эпизод нужно повторить. Обучение использует нагрузку 0.7, новые дорожные seeds 10000–10029 и исходные веса D3QN с прогнозом. Оптимизатор и replay buffer для дообучения созданы заново; перенесены именно веса сети. Четыре новых входных признака — время без зелёного по подходам. Недопустимые действия исключаются и в exploration, и в greedy policy, и в Double-DQN target.

Ограничение резервирует время для последовательного обслуживания остальных подходов: 3 с жёлтого и 10 с зелёного на действие. Это ограничение на светофорный план в данной симуляции, а не гарантия отсутствия ДТП или малого времени поездки. Новая reward остаётся efficiency-only (`w=1`). В сравнении отдельно сохранён вариант с исходными весами и тем же ограничением, чтобы не приписывать эффект ограничения дообучению.

Проверочные seeds 500–502 относятся к временной части validation, новые тестовые seeds 1000–1003 — к прежней временной test-части PeMS08. Это новые сценарии спроса, а не новый независимый датасет. 60 тестов = 5 контроллеров × 4 seeds × 3 нагрузки. Один seed обучения не позволяет доказать устойчивость RL-метода в целом.

## Установка

Рекомендуется Python 3.12, 8 GB RAM или больше. Этот запуск выполнен на CPU; GPU не требуется.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

Точные версии выполненного эксперимента находятся в `requirements-lock.txt` и `artifacts/environment.json`. PyTorch устанавливается первым из официального CPU-индекса, чтобы на ноутбук не загружались ненужные CUDA-зависимости.

## Быстрый запуск обученного агента

Выполнять команды из распакованного каталога проекта:

```bash
python -m atsc.data
python -m atsc.network
python -m atsc.control evaluate --name d3qn_forecast --seed 200 --saturation 0.7 --record
```

Для просмотра готового анализа откройте `notebook/Results_Evidence.html`; для движения машин запустите `demo.cmd`. Новые сценарии используют данные PeMS, источник и SHA-256 которых записаны в `data/manifest.json`. Отдельная копия PeMS08 для воспроизведения анализа приложена в `notebook/evidence/data/`.

Исторические генераторы `atsc.replay`, `atsc.report` и `atsc.continuation_report` сохранены для явного воспроизведения старых HTML-экспортов; для текущей демонстрации они не нужны.

## Повторить обучение

```bash
python -m atsc.forecast --dataset PEMS04 --epochs 6
python -m atsc.forecast --dataset PEMS08 --epochs 6
python -m atsc.finetune
python -m atsc.control calibrate
python -m atsc.control train --name d3qn_no_forecast --episodes 30
python -m atsc.control train --name d3qn_forecast --episodes 30
python -m atsc.control train --name d3qn_safety --episodes 30
```

Или запустить весь последовательный pipeline:

```bash
python run_pilot.py --evaluate
```

Повторное обучение перезаписывает соответствующие веса. Перед новым экспериментом сохраните копию архива. Оценщик повторно использует JSON прогонов только при совпадении длительности и SHA-256 checkpoints. Для другого дизайна эксперимента или других данных нужно перенести старый каталог `artifacts/evaluation`, чтобы не смешать разные исследования.

## Оценка на новых сценариях

```bash
python -m atsc.experiment --names d3qn_forecast,d3qn_safety --split tune --start-seed 100 --n-seeds 10 --loads .7
python -m atsc.experiment --names webster,max_pressure,forecast_rule,d3qn_no_forecast,d3qn_forecast --start-seed 200 --n-seeds 10 --loads .4,.7,.95 --workers 3
python -m unittest discover -s tests -v
```

Для другого веса награды можно обучить отдельный checkpoint, например `python -m atsc.control train --name d3qn_safety_w075 --weight .75 --episodes 200`. Этот запуск в архиве не выполнен.

Для более длительного обучения увеличьте `--episodes` и `--epochs`. Запуск агента с `--seed 1` создаёт отдельные веса; полноценная оценка нескольких обученных политик требует передавать соответствующий `training_seed` в `atsc.control.evaluate`. Это не считается выполненным автоматически при десяти seeds дорожного спроса.

После tuning safety-вариант добавляется к финальным тестам только при прохождении критерия. Если он отклонён, его веса и все tuning-результаты сохраняются, но финальная оценка проводится для efficiency-only агента. Это заранее заданное правило выбора; отклонённый кандидат не выдаётся за улучшенную безопасную модель. При желании его можно отдельно проверить через `--names d3qn_safety`.

## Что именно реализовано

- Искусственный четырёхсторонний перекрёсток: 600 м на подход, по три входящих полосы; правая, прямая и левая траектории. Разрешён один подход за раз, четыре фазы.
- 90% легковых и 10% грузовых машин. Стохастические прибытия Poisson с изменяющейся интенсивностью из PeMS08. Это отличается от Weibull, предложенного в постере.
- Нагрузка 0.4/0.7/0.95 масштабируется относительно **принятой** мощности 1350 машин/час/подход. Это номинальный уровень нагрузки, не эмпирически установленная степень насыщения SUMO. При 0.95 возможна перегрузка.
- Шаг SUMO 0.5 с; не менее 10 с зелёного; 3 с жёлтого при смене. При смене длительность действия 13 с, при удержании 10 с. Discount DQN учитывает эту разницу.
- Час прогрева на фиксированном плане и час измерения. Терминальный шаг обрезается ровно на границе окна наблюдения.
- T-GCN: графовые операции в GRU-подобных воротах, 24 скрытых признака, общие веса по узлам. Для всех обучаемых прогнозаторов добавлен одинаковый persistence residual.
- Прогноз: 12×5 минут истории → 3×5 минут будущего; обновление через 5 минут. Online-история формируется фактическими индукционными датчиками SUMO в 50 м от стоп-линии. Будущие фактические значения агент не получает.
- PeMS: все 307/170 датчиков, хронологическое 60/20/20; train stride 3, validation stride 3, test stride 1; нормализация только по train. Нули сохранены; невалидные значения заполняются причинно предыдущим наблюдением.
- D3QN: Double DQN, dueling head, prioritized replay с importance weights, сеть 256–256, Adam 1e-4, gamma 0.99 на 10 с, batch 32, target update 500 шагов, epsilon от 1 до .05.
- Сравнения: округлённый к 10 с Webster fixed-time, Max Pressure, пропорциональное выделение зелёного по прогнозу, D3QN без прогноза, D3QN с прогнозом и efficiency-only reward, D3QN с прогнозом и safety weight.
- Сохранены отдельные checkpoints и фактическая история всех выполненных эпизодов.

## Как читать метрики

Основная численная метрика этого пилота — `delay_per_requested_vehicle_s`: интеграл потери скорости всех находящихся в сети машин плюс ожидание машин, которые SUMO пока не смог вставить в сеть, за час измерения; результат делится на число машин, запланированных к прибытию за этот час. Учитывается затор снаружи сети, поэтому контроллер не может скрыть его через запрет въезда.

**Это не точная средняя величина полного travel time − free-flow travel time для завершивших поездку машин из формулы постера.** На конечном часовом окне присутствуют машины прогрева и незавершённые поездки. В отчёте также показываются throughput, остаток в сети и очередь на вставку. Для полного воспроизведения формулы нужен отдельный когортный эксперимент с доездом всех машин до назначения и корректным учётом незавершённых поездок.

Safety: TTC считается только для следующей и ведущей машины на одной полосе. Физический bumper gap делится на положительную скорость сближения. Конфликт — вход пары в диапазон `0 < TTC < 1.5 s`; после выхода и повторного входа возникает новое событие. TET — накопленная длительность таких состояний. Это proxy для задних столкновений; боковые и пешеходные конфликты не оцениваются. Нормирование — на 1000 покинувших сеть машин за окно. Такие события не равны авариям.

Награда использует нормализованные интегральную задержку и число TTC-событий. Нормировочные константы измерены на трёх фиксированных **обучающих** сценариях. В пилоте safety-вес сравнивается только для `w=0.5` и `w=1`; `w` — вес эффективности. Кандидат допускается, только если на tuning-сценариях конфликты уменьшились, а задержка выросла не более чем на 5%.

## Ограничения относительно постера

Это законченная рабочая реализация **одного пилотного стенда**, а не выполненный полностью исследовательский протокол.

- Нет дорожной геометрии Астаны и эксперимента на сетке 3×3. Ни одна синтетическая сеть не выдаётся за реальный перекрёсток.
- Один seed обучения прогнозаторов и один seed обучения каждого агента. Seeds оценки меняют дорожные сценарии, а не обученные веса.
- 6 эпох прогнозаторов и сокращённое обучение RL; сходимость и оптимальность не заявляются.
- Нет полного sweep safety-весов 0/.25/.5/.75; в выполненном пилоте — один кандидат.
- На изолированном перекрёстке граф четырёх входящих подходов берётся единичным: пространственные связи upstream-сети отсутствуют. Fine-tuning сохраняет общие веса, но не проверяет пространственную переносимость на сеть города.
- Нет пешеходов, обработки отказов датчиков и формальной гарантии устойчивости. В первоначальных агентах нет ограничения максимального красного; отдельное продолжение добавляет ограничение 120 с без зелёного. Не предназначено для реального управления дорогой.
- Открытые данные, подготовка, обучение и тестирование сохраняют временное разделение; однако перенос калифорнийских freeway-профилей на перекрёсток остаётся предположением.
- Wilcoxon оценивает парные различия на сценариях для конкретных обученных весов. Это не доказательство устойчивости по seeds обучения. Проверки exploratory; полного контроля множественных сравнений нет.
